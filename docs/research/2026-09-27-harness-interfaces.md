# 本地浏览器 UI 与 TUI 方案研究

日期：2026-09-27。状态：研究与推荐方案，未实现产品界面。用户已确认单机本地、本地浏览器与终端同等重要；后续明确否决 Textual 全屏方向，要求参考 ccusage 的轻量终端工具。本文据此修订，不再将全屏应用或交互镜像列为要求。

## 1. 产品边界

两个入口共用计量与查询口径，但不强求交互镜像。网页承担深入交互；终端通过一次性命令、筛选参数、会话详情报表与 JSON 完成查询，保留滚动历史。终端重要不等于需要一个全屏应用。

- Web 承担鼠标友好的趋势选择、高密度比较、表格和详情联动。
- 终端采用 ccusage 式执行即退出、响应式表格/紧凑列表；适合 SSH/tmux、复制、管道。
- 复用现有 Rich 输出能力，不引入 Textual、不接管键盘、不建立多页焦点状态机。
- 本轮不做桌面壳、账号、多机汇总、团队权限、预算拦截、聊天全文搜索、LLM 自动归因。

## 2. 现有输出为什么不能套壳复用

用户已确认图片兼容性差、排版差、尺寸自适应体验差，无需重跑来证明用户观察。

源码补充说明：

- `render/tables.py` 固定度量列，许多视图同时展示大量指标；`_metric_row` 依赖 `cells_before + 9`。需要改变列预算和信息密度，不需要因为它是打印表格而替换成全屏应用。
- `render/charts.py` 已按终端列数计算图宽，不能说完全没有尺寸处理；但本轮替代能力比较已明确排除所有绘图。
- `cli.py` 直接分派不同 renderer，部分图表/JSON 成本自行计算。新界面必须消费统一数值，不能各自复制计算。
- `stats.apply_filters` 原地修改模型集合。常驻进程若缓存并复用这些对象，会污染后续查询；共享核心需要无副作用查询。

研究代理实测现有 CLI：7 天约 1.74 秒、30 天约 5.83 秒、全历史约 5.26 秒；全历史当前输出 1428 个会话、130295 个计量调用。数据目录约 5.2GB、1501 个文件。以上是本机研究截面、非严谨冷/热缓存基准，不能推导框架性能排名；但足以说明不能在每次筛选交互时全量解析日志。调用数是当前实现口径，不是审计后的真实网络请求总数。

## 3. 三种图形界面方向

| 方向 | 首页回答的问题 | 优点 | 代价 | 结论 |
|---|---|---|---|---|
| A. 账本 + 趋势 | 消耗在哪里，哪些数字可信？ | 模型/来源/项目横切自然，数值对齐，窄屏易收缩 | 视觉冲击弱，需要认真处理密度 | 推荐主界面 |
| B. 时间线/泳道 | 何时、哪些会话或子代理产生消耗？ | 并发与跨夜形态清晰 | 上千会话首屏拥挤，窄屏与无障碍成本高 | 仅用于所选会话家族的详情 |
| C. 追溯树 | 一笔用量来自哪个会话和调用？ | 对账、父子归属清楚 | 模型等跨树维度变得不直接，深树导航重 | 仅用于会话追溯 |

### 推荐首页线框

```text
日期范围 · 时区 · 来源筛选 · 搜索             数据覆盖 / 更新时间
──────────────────────────────────────────────────────────
已知估算成本 + 缺价提示      Tokens       已记录调用
趋势图：当前筛选结果，支持选择区间，提供等价日期输入
──────────────────────────────────────────────────────────
分组：来源 / 模型 / 项目 / 会话 / 用途       筛选面包屑
名称               Tokens     成本与性质     调用  │ 当前选择详情
来源/模型/项目行       …          …           …   │ 构成、依据
                                                  │ 下钻入口
──────────────────────────────────────────────────────────
当前快照 · 部分失败/缺失记录提示 · 显式重新扫描
```

不固定强制用户按 harness → model → project 顺序下钻。选择一个维度值添加筛选后，用户仍能自由切换分组；面包屑表达约束，不伪装成所有维度天然构成一棵树。

### 视觉建议

采用「分析账本」而非装饰性 dashboard：中性背景、清楚的层级、细分隔线、一个强调色、语义警告色；数字等宽且右对齐，单位固定；完整模型身份可查看/复制，不能把所有模型都截成相同前缀。明暗主题均可读，图表颜色不承载唯一信息。避免满屏卡片、3D 贡献图、大饼图和装饰动效。

中文界面优先；标识符、模型名、provider 保留原文。字体由本地系统中文字体与等宽数字回退组成，不通过 CDN 拉字体。视觉方向属于推荐，尚未用高保真原型验证审美，不声称“已经好看”。

## 4. 图形界面交互与状态

### 信息层级

- 总览：当前窗口用量、已知估算成本、缺价记录/模型数、来源覆盖与更新时间。
- 明细：按 harness/provider/model/project/session/purpose 分组，筛选与排序可组合。
- 会话：本会话自身用量和包含子代理的家族用量分开标注，避免把父小计再加子行。
- 调用：时间、来源类型、模型/provider、用途、token 分量、费用性质与依据。
- 数据源：扫描状态、记录覆盖、适配器版本、失败/未知记录数；路径不输出到外部服务。

### 数字表达

未知不是 0。成本的“性质”（来源估值、价目估值、实际账单）与“完整性”（完整、部分未知、未知）是两个维度，不能混为单个枚举。当前已确认来源不提供实际账单，因此首页不放一张永远空着的“真实账单”卡；未来确有账单来源时才显示并单列。

缺数据时默认写“已知小计，不含 X”，不要一律用 `≥`：只有所有已计金额可靠且缺项非负时，才有数学上的下界保证。缺价金额不得在饼图中变成零成本份额；费用占比明确标注“已知成本内部占比”。

价格假设、缓存回退、服务档位折算可展开；不把供应商字段名 `cost` 等同真实扣费。

### 状态矩阵

| 状态 | 行为 |
|---|---|
| 首次扫描 | 显示进度与取消；已有快照可继续浏览并标过期 |
| 查询无结果 | 保留筛选，提供清除筛选；与“没有数据源”区分 |
| 没有可用来源 | 展示支持的来源与路径诊断，不显示误导性的零成本 |
| 单源解析失败 | 保留其上次可用状态或明确排除，汇总标部分；其他来源可用 |
| 价格缺失 | Tokens 可查，金额未知，解释价格来源，不强制联网 |
| 后台刷新 | 不抢焦点、不重置排序/滚动；更新完成后切换同一快照 |
| 多次快速筛选 | 丢弃过期响应，避免旧查询覆盖新筛选 |
| 数据源删除/格式变更 | 明确状态，不自动把上次历史当新零值；重建有范围与恢复语义 |

刷新流程只写本工具自己的缓存，不写源日志或 OMP 的统计库。读取 API 不触发扫描；显式重新扫描用 POST。网页标签页关闭并不能可靠等价于进程停止：前台进程由 Ctrl-C/显式退出停止，不能依赖浏览器 unload 回调作为唯一清理机制。

### 响应式验收目标

| 视口 | 布局 | 验收 |
|---|---|---|
| ≥1280px | 账本与详情双栏 | 数字对齐、完整筛选、表头固定，长模型名可查看 |
| 768–1279px | 单主表，详情抽屉/独立页 | 隐藏次要列，筛选可折叠，主界面无整页横向滚动 |
| 320–767px 或高缩放 | 单列列表、详情单独页 | 名称、tokens、成本性质可见；趋势有文字/表格替代 |

共同验收：纯键盘能完成筛选、排序、详情和返回；焦点可见；关闭弹层恢复焦点；状态不只靠颜色；遵循 [WCAG Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)。追溯树如用 treegrid，遵循 [APG treegrid](https://www.w3.org/WAI/ARIA/apg/patterns/treegrid/)，不能仅添加 ARIA 属性而不实现键盘行为。

## 5. 轻量终端技术选择

推荐保留 Python + Rich，重做报表布局，而不是换全屏框架。Textual、Ratatui、Bubble Tea 和 Ink 可实现复杂交互，但当前不以这类应用模型作为终端目标。也不将用户认为“重”误写成未经测量的 CPU/内存结论：这里首先是交互、依赖与维护边界。

[ccusage 官方说明](https://github.com/ccusage/ccusage/blob/main/apps/ccusage/README.md) 明确一次性 daily/weekly/monthly/session 报表、JSON、窄终端自动 compact（文档阈值 100 列）和 `--compact`。值得借鉴的是执行模式和列策略，而不是照搬具体阈值或技术栈。

[Rich Console](https://rich.readthedocs.io/en/stable/console.html) 已提供当前终端尺寸、TTY/颜色检测与宽字符排版；不需要为了响应式输出增加 Textual。

## 6. 终端输出契约

- 默认打印一次并退出，不清屏、不进入 alternate screen、不隐藏光标、不捕获键盘；结果留在滚动历史中。
- 宽终端显示更多指标，中等宽度保留名称、tokens、成本与必要状态；窄终端转为分块/纵向字段，不把所有列挤进一行。
- 列隐藏只改变显示，不改变筛选或数值；完整指标可通过详情报表/JSON查询。显示缩写金额或 K/M 数值时标明展示精度，JSON保持精确。
- 名称优先可识别；过长时换行或在详情输出完整值，不把多个模型都截成同一前缀。
- 输出前探测宽度，允许显式 width/compact 覆盖。已经打印进历史的表格不能在进程退出后重新计算列；终端自身重流与应用动态重排是两回事。扩大后重新执行即可得到新布局。
- 高度不作为强制全屏预算，不自动截断结果；长报表使用终端历史或用户显式的外部分页器。不默认进入分页器。
- 过滤和下钻用参数或独立详情命令，不做焦点、弹层、快捷键页面。
- 非TTY默认无色、无控制序列；JSON不受列宽影响。纯文本管道不固定250列伪装响应式；需另行定义稳定可读的换行策略。
- watch不是默认需求。若未来确认需要，单独设计当前屏幕内的有限刷新，不能把“可选watch”偷换成全屏TUI。
- 本轮用临时Rich探针验证尺寸/中文/管道边界，具体实测见后续轻量终端报告；不据框架文档承诺所有终端兼容。


## 7. 共用核心与推荐实现栈

**推荐而非已实施：Python 查询/索引核心 + 本地 HTTP API + TypeScript/React 网页 + Rich 轻量终端报表。**

- Python 继续承接现有 Codex 计量知识，但调用级记录、纯查询、费用状态需要改造，不能原封不动复用 `Session`。
- SQLite 自有可重建索引，支持两端启动和重复筛选。读取查询不全量解析源日志。已观察秒级扫描，因此建议纳入方案；增量细节先用代表性数据探针确定，不先建常驻 daemon。
- `Summary / Breakdown / Series / SessionDetail / Calls / Coverage` 是共享查询结果。终端在进程内查询并输出报表；Web 通过 JSON 访问，不互相解析文本。
- 共同 `FilterState`：时间/时区、harness、provider、model、project、session、agent kind、purpose、tier、分组、排序、分页。所有响应带快照版本和完整性。
- 前端构建产物随 Python 包发行，终端用户不需 Node；不使用 CDN。React 是复杂交互状态下的常规选择，不需要 SSR/Next.js。
- HTTP 推荐小型 ASGI 应用，复用成熟请求/响应与中间件能力，不自写一套 `http.server` 安全框架。FastAPI/Starlette 具体依赖需在实施计划中锁定；这不改变查询核心。
- 表格先服务端分页，按实际渲染规模决定虚拟滚动；不能因为总记录有十万条就一次发送全部调用给浏览器。
- 图表以可访问的时间趋势/条形为主；Chart.js 或 uPlot 按交互与数据量选择，不能将库名当成 UI 设计。初始优先统一一种图表库，不并引两套。
- 项目先按来源记录的完整 cwd 区分，不只用 basename；git root/worktree 合并需要明示规则，不能默默把不同项目并在一起。
- 默认中文文案与原始技术标识，不在本轮追加完整国际化平台。

未来入口区分本地 Web、一次性终端报表和 JSON，不预设新增 `tui` 命令。产品命名与旧命令迁移属于实施前决策，本轮不创建别名或兼容层。

## 8. 本地网页安全与生命周期

1. 仅 loopback 监听；端口可选择，启动明确打印实际地址。普通查询完全离线。
2. 校验 Host；禁用任意跨源读取，不能只靠“不设置 CORS”应付 DNS rebinding。
3. 启动会话可用一次性 token 引导。推荐放 URL fragment 后由本地页面兑换 HttpOnly、SameSite cookie，清除地址中的 token，避免查询字符串进入 HTTP 日志/Referer；不把 token 印入持久日志。
4. 查询 GET 无副作用；扫描、修改本工具设置和显式价格更新走 POST，并校验 Origin/CSRF。
5. 不提供任意路径读取 API；所有来源路径需来自已配置的 source root，规范化并限制访问。API 不返回 prompt/message、密钥或工具参数。
6. 静态资源内置，CSP 限制 self；不套用开发服务器作为最终产品服务器。
7. 服务跟随显式前台进程生命周期，不依赖标签页关闭信号，也不自动安装后台服务。

这是方案的安全边界，不是对竞品漏洞已利用的声称。[Vite 官方安全说明](https://vite.dev/config/server-options.html) 明确任意 Host 会造成 DNS rebinding 风险；[Python http.server](https://docs.python.org/3/library/http.server.html) 不推荐生产用途。OMP 的 `GET /api/sync` 是带副作用的设计参考反例，不能照搬。

## 9. 不选的图形技术路线

- **Tauri**：原生壳、sidecar 和系统 WebView 增加平台打包/依赖；用户已选浏览器。[Sidecar](https://v2.tauri.app/develop/sidecar/)、[WebView 差异](https://v2.tauri.app/reference/webview-versions/)。
- **Electron**：桌面分发成熟，但需维护 Chromium 更新、签名及安全桥接，当前无桌面特性需求。[安全文档](https://www.electronjs.org/docs/latest/tutorial/security)。
- **pywebview**：可复用 Python，但 Linux GTK/Qt 依赖仍在；不消除桌面发布成本。[文档](https://pywebview.flowrl.com/guide/)。
- **textual-serve**：把字符终端放进浏览器，不等于独立图形分析界面。[项目](https://github.com/Textualize/textual-serve)。
- **静态 HTML 导出**：可能有用，但用户没有要求，不列为本次必须交付的第三入口。

## 10. 后续验收矩阵

- Web：1280+、1024、768、320px；缩放、长中文/模型名、仅键盘、空态/部分失败/未定价；真实浏览器检查，而非只看截图。
- 终端：120/80/60/40列、中文宽字符、NO_COLOR、pipe/JSON；实测每次输出按宽度选择布局，无清屏/备用屏幕/键盘捕获。退出后的历史不要求动态重排。
- 两端：同一快照/筛选/时区/价格基准，记录集合、分组小计、趋势总计、家族边界、费用状态一致。
- 性能目标建议：已索引后的常用筛选在代表性本机数据上 P95 ≤200ms，显示反馈不等待全量重扫；首次索引显示进度，可取消。这是验收目标，不是已实现结果。
- 单源失败不隐瞒；数据与价格缺失不填假零；扫描更新不抢焦点。
- 非TTY不泄漏控制序列，JSON 可解析；默认无外网请求、源数据不被写入；退出后本工具端口关闭。

## 11. 主代理对研究建议的裁决

- 采纳两端都重要、账本首页、调用级记录、用途/覆盖展示、共享查询；按用户最新指示撤回 Textual 和全屏 TUI 推荐，改用轻量报表。
- 不采纳“永远保留所有旧图表实现”的默认建议。若正式选择新双入口，旧终端图片路径可在明确切换批次整体退役，不做长期双轨。
- 不采纳“账单实际是首屏必备卡片”：目前没有此数据来源。
- 不采纳“关闭标签页即停止服务”：该生命周期不可靠。
- 不采纳“必须一次传完十万条再虚拟化”：服务端分页是更小的起点。
- 不采纳自动增加静态 HTML 导出、SSH public-url、多机或 Git 归因功能；这些不是当前需求。
- 调研中的源码能力、性能样本与设计目标分开记录；本轮没有已验证的新 UI/TUI。
